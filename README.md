# Student Task Tracker

A beginner-friendly Flutter + Firebase app for students to manage their tasks:
create, edit, complete, filter and sort tasks by subject and due date.

**Stack:** Flutter, Dart, Firebase Authentication, Cloud Firestore, Material 3.

---

## 1. Prerequisites

- Flutter SDK installed (`flutter --version`)
- Android Studio with the Android SDK installed
- A Google account (for Firebase)
- Node.js is **not** required unless you install the FlutterFire CLI via npm alternative — we use `dart pub global activate` below instead

---

## 2. Set up the Flutter project

This folder already contains the `lib/` source code and `pubspec.yaml`.
It does **not** contain the native Android/iOS project scaffolding (that's
generated locally, since it's large and machine-specific).

```bash
# From the parent folder containing this project:
flutter create --org com.example student_task_tracker_scaffold

# Copy the generated 'android' folder into this project
# (Windows PowerShell example — adjust paths as needed)
Copy-Item -Recurse student_task_tracker_scaffold\android student_task_tracker\

# Then delete the scaffold folder, you don't need it anymore
Remove-Item -Recurse student_task_tracker_scaffold
```

> Alternative: if you already ran `flutter create student_task_tracker`
> yourself before receiving these files, just copy the contents of
> `lib/`, `pubspec.yaml`, `firestore.rules`, and `.gitignore` from this
> package into your existing project, overwriting the defaults.

Then install dependencies:

```bash
cd student_task_tracker
flutter pub get
```

---

## 3. Firebase setup

1. Go to the [Firebase Console](https://console.firebase.google.com/) and
   create a new project.
2. Install the FlutterFire CLI (one-time):
   ```bash
   dart pub global activate flutterfire_cli
   ```
3. Make sure the Firebase CLI is installed too:
   ```bash
   npm install -g firebase-tools
   firebase login
   ```
4. From your project root, run:
   ```bash
   flutterfire configure
   ```
   - Select your Firebase project
   - Select **Android** as the platform
   - This will overwrite `lib/firebase_options.dart` with your real
     project config, and generate `android/app/google-services.json`.
5. In the Firebase Console:
   - Go to **Authentication → Sign-in method** → enable **Email/Password**.
   - Go to **Firestore Database** → create a database (start in
     **production mode**, since we provide our own security rules).

### Deploy the security rules

```bash
firebase init firestore   # link this project to your Firebase project, if not already done
firebase deploy --only firestore:rules
```

This uploads `firestore.rules` (included in this project) so that users
can only access their own data.

---

## 4. Running the app

Plug in an Android phone with USB debugging enabled, **or** start an
Android emulator from Android Studio (Device Manager → launch a virtual
device).

Check what Flutter sees:

```bash
flutter devices
```

Then run:

```bash
flutter run
```

Hot reload works as usual — press `r` in the terminal after making changes.

---

## 5. Testing checklist

- [ ] Register a new account → check `users/{uid}` doc appears in Firestore
- [ ] Log out, log back in with the same credentials
- [ ] Close and reopen the app → should stay logged in
- [ ] Create a task → appears in the task list and pending count updates
- [ ] Edit a task → changes are saved
- [ ] Mark a task complete → moves between Pending/Completed filters
- [ ] Delete a task → disappears from the list
- [ ] Create a second account and confirm it **cannot** see the first
      account's tasks (tests the Firestore security rules)

## 6. Push to GitHub

```bash
git init
git add .
git commit -m "Initial Flutter student task tracker"
```

Then on GitHub, create a new empty repository (no README/gitignore, since
you already have them), and run:

```bash
git remote add origin https://github.com/YOUR_USERNAME/student_task_tracker.git
git branch -M main
git push -u origin main
```

The included `.gitignore` keeps build artifacts and local config out of
version control. `lib/firebase_options.dart` is safe to commit — it
contains client identifiers, not secret keys; access is controlled by
`firestore.rules`, not by hiding this file.

## Project structure

```
lib/
  main.dart                     # App entry point, Firebase init, auth routing
  firebase_options.dart         # Generated by flutterfire configure
  models/
    task_model.dart             # Task data model
  services/
    auth_service.dart           # Register / login / logout
    firestore_service.dart      # Task CRUD operations
  screens/
    login_screen.dart
    register_screen.dart
    dashboard_screen.dart       # Summary + task list + filters + FAB
    add_edit_task_screen.dart   # Shared create/edit form
    profile_screen.dart         # User info + logout
  widgets/
    custom_text_field.dart
    task_tile.dart
firestore.rules                 # Per-user data access rules
```
